# Fallout 34 Installer 0.9.102 한국어 원본 ESM 실험 수정

**시험용: 플러그인 생성 성공. 전체 설치, 전체 문구와 비영어권 문자 보존 및 인게임 안정성 미검증**

## 2026-11-28 추가 시험

- 세 번째 수정 지점 `f34.systems.fo3_settings`를 추가했습니다. 실제 한글 FO3 원본의 GMST 문자열 17개가 CP1252로 디코딩되지 않아 이 지점에서 중단됐습니다.
- 사용자 보유 0.9.102 원본 실행 파일의 SHA-256을 확인하고 재현 가능한 별도 시험본을 생성했습니다. 기존 설치기는 변경하지 않았습니다.
- FFmpeg와 texconv 경로를 지정해 두 게임의 플러그인 단계를 `--no-install`로 별도 생성한 결과 각각 종료 코드 0이었습니다. 현재 입력에 대한 보고서에는 `build_failed`가 나타나지 않았습니다. 이전 실행과 현재 입력 레코드 수가 다르므로 이전 스크립트 실패 원인을 해결했다고 단정하지 않습니다.
- 원본과 동일 FormID에 대응하는 주요 PERK/WEAP/ARMO/MISC/AMMO/NPC_/ALCH 이름 중 FO3 2,049/2,085건, FNV 4,825/4,869건이 바이트까지 동일했습니다. 차이에는 방어구 분류 접두어가 포함됩니다. 다른 필드 및 누락 항목은 이 수치에 포함되지 않습니다.
- 변환된 파일은 `work/fo3-diagnostic-utf8-v5/Data/Fallout34.esm`, `work/nv-diagnostic-utf8-v5/Data/FalloutNV34.esm`입니다. 전체 설치 및 인게임 동작을 검증한 파일이 아닙니다.

### 미번역 단말기 보완

- 기존 한글화 결과에서 영문으로 남은 단말기와 메모 본문을 검토해 추가했습니다. 실제 0.9.102 시험 ESM 기준으로 FO3 40개, FNV 39개 필드가 추가로 적용됩니다. 원본과 메모용 단말기가 같은 글을 표시하는 경우 둘 다 포함한 수량입니다.
- 0.9.102 추가 데이터는 `data/canonical/fo3.v09102-extra.json`과 `fnv.v09102-extra.json`에 저장합니다. FormID·종류·필드 순서·EditorID와 해당 영문 바이트 SHA-256이 일치할 때만 적용합니다. 기존 항목에서 원문이 바뀐 경우에도 검증한 별도 SHA-256에만 동일한 기존 한국어를 적용합니다.
- 조사한 범위는 BOOK/TERM/LSCR/PERK/MESG의 일부 표시 필드입니다. 본문 후보 중 150자 이상 영문은 처리했지만, 내부 식별자처럼 보이는 짧은 영문과 그 밖의 레코드 유형에 실제 미번역이 남아 있을 수 있습니다. 모든 미번역이 해결됐다는 뜻은 아닙니다.

### 짧은 영문과 추가 레코드 점검

INFO 대화의 `More...`, `Goodbye.` 및 일부 문맥이 확인된 짧은 대사를 추가했으며, 0.9.102 시험본에서 FO3 985개와 FNV 18,083개 필드에 적용됩니다. MGEF 효과명과 일부 의상·인물 이름은 FO3 34개와 FNV 61개를 추가했습니다. 각 위치와 원문 해시가 정확히 일치할 때만 적용합니다. 작별 문구는 기존 번역의 용례에 맞춰 `안녕.`으로 통일했습니다.

추가 검색에는 내부 코드·파일명·개발용 음성 지시문도 포함됩니다. 이를 일반 대사로 취급하지 않았습니다. 이후 메모 제목 455개와 연결된 단말기 제목을 번역하고, 불일치 항목에서 영문 대사와 깨진 문구 등을 추가로 보완했습니다. 레코드 연결과 생성된 ESM의 텍스트를 확인했지만 게임 화면에서 각 항목을 확인한 것은 아닙니다. 전체 레코드의 인게임 노출 여부와 번역 완성도를 보증하지 않습니다.

## 재현 오류

2026-11-22 공식 설치기 0.9.102에서 FO3/FNV의 plugin 변환 단계가 실패했습니다.

- FO3: f34/esm.py:27 Subrecord.zstr가 UTF-8 '중공군 장교의 검'을 CP1252로 읽다 실패(0x90). 뒤따르는 Havok 오류가 실패 창에서 위에 나타날 수 있습니다.
- FNV: 동일한 Subrecord.zstr가 UTF-8 '스위치블레이드'를 CP1252로 읽다 실패(0x9d).
- 게임 설치본의 FO3/FNV ESM·ESP에 이미 UTF-8 한국어가 적용되어 있었으며, 백업본에는 영문 이름이 남아 있었습니다.

공식 변환기는 Nuitka로 컴파일한 payload/app/f34conv.exe로 동작합니다. 나머지 payload/app/f34/*.py는 플레이스홀더입니다. 공식 GitHub에 변환기 코드가 공개되지 않아 소스 수준의 UTF-8 우선/CP1252 폴백 구현은 할 수 없습니다.

## 시험용 바이너리 수정

tools/patch_fallout34_09102_utf8.py는 **정확한 0.9.102 바이너리 SHA-256**을 검사한 다음 Nuitka 함수 상수 테이블의 다음 세 지점을 같은 길이의 유효한 UTF-8 인코딩 별칭 'utf-8 '으로 바꿔 **별도의 실행 파일**을 만듭니다.

- f34.esm.Subrecord.zstr: 소스 ESM의 텍스트를 읽는 공통 함수
- f34.ctx.zstr: 변환 결과 ESM의 텍스트를 기록하는 공통 함수 (기존 CP1252 'replace'로 인한 '?' 손실 방지)
- f34.systems.fo3_settings: FO3 게임 설정 문자열 읽기

다른 CP1252 사용 부분과 게임 파일은 수정하지 않습니다.

사용법 (저장소 루트에서 PowerShell로 실행):

    python tools/patch_fallout34_09102_utf8.py "C:\path\to\Fallout34_Installer_v0.9.102\payload\app\f34conv.exe" "D:\Codex_Trans\34\work\Fallout34-0.9.102-utf8\payload\app\f34conv.exe"

원본 설치기 폴더를 별도 복사한 경우 복사본의 payload/app/f34conv.exe만 수정본으로 대체해 시험합니다. **수정 실행 파일이나 공식 설치기 전체를 GitHub에 배포하지 마세요.**

## 한계와 검증

- 위 세 지점만 대상으로 합니다. 기존 CP1252 문자로 저장된 텍스트가 입력 디코딩 함수로 전달되면 새로운 UnicodeDecodeError가 날 수 있습니다.
- 변환기의 다른 decode/encode cp1252 호출은 남아 있으므로, 한국어가 다른 경로에서 '?'로 바뀌거나 후속 단계에서 실패할 수 있습니다.
- 먼저 --only plugin 및 --variant 명령으로 게임 설치 없이 검증하고, 새 ESM의 구조·지형·한글 출력 결과를 확인해야 합니다. 기존 FO3/FNV/FO4 원본을 덮어쓰지 마세요.
- 공식 소스를 제공받으면 Subrecord.zstr의 텍스트 전용 처리를 UTF-8 strict 우선 -> CP1252 폴백으로 바꾸고, 메타데이터 식별자 및 바이너리 레코드 처리와 분리해야 합니다.
